# SRS: ai_news_telegram

- 작성일: 2026-08-05
- 작성자: devjan
- 상태: 초안
- 관련 PRD: [`PRD.md`](./PRD.md) (배경/입출력/처리흐름 개요는 PRD가 원본이며, 이 SRS는
  구현에 필요한 요구사항을 더 세분화한다)

## 1. 개요
Hacker News에서 AI 관련 스토리를 수집해 규칙 기반으로 "기술"/"비즈니스" 카테고리로 분류하고,
카테고리별 상위 후보를 Claude API에 1회 전달해 최종 Top5/Top5와 한국어 요약을 생성한 뒤
텔레그램으로 발송한다. `daily`(최근 24시간)와 `weekly`(최근 7일) 두 실행 모드를 지원하며,
정기 실행 스케줄링과 뉴스 소스 확장은 이 스킬의 범위 밖이다 (PRD 7절).

## 2. 용어 정의
| 용어 | 정의 |
|---|---|
| 후보 풀 | 규칙 기반 점수/키워드 필터링을 통과해 Claude API 호출 대상으로 넘어가는 스토리 집합 |
| Hot 점수 | `points + comments * 가중치`로 계산하는 규칙 기반 인기 점수 (가중치는 2.0으로 확정, Phase 1 구현 시 댓글이 단순 동의 표시인 points보다 적극적 관여를 나타낸다고 보고 결정) |
| 카테고리 | "기술"(모델/연구/오픈소스 등) 또는 "비즈니스"(투자/인수/규제/매출 등) 중 하나. 키워드 매칭으로 규칙 기반 분류 |
| 발송 이력 | 이전 실행에서 이미 텔레그램으로 보낸 HN item id 목록. 중복 발송 방지에 사용 |
| 부분 부족 | 한 카테고리의 최종 후보가 5건 미만인 상태 (실패로 취급하지 않음) |
| 완전 실패 | HN 검색, Claude 랭킹/요약, 텔레그램 발송 중 하나라도 예외로 중단된 상태 |

## 3. 기능 요구사항
| ID | 요구사항 설명 | 우선순위 |
|---|---|---|
| FR-1 | `.env`에서 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `ANTHROPIC_API_KEY`를 로드하고, 하나라도 없으면 실행 시작 전에 실패 처리한다 | 필수 |
| FR-2 | `--mode` 인자로 `daily`/`weekly`를 받으며, 그 외 값이거나 인자가 없으면 실행 시작 전 실패 처리한다 | 필수 |
| FR-3 | `daily`는 `created_at_i` 기준 최근 24시간, `weekly`는 최근 7일 이내 게시된 HN 스토리만 검색 대상으로 한다 | 필수 |
| FR-4 | 지정된 AI 관련 키워드 목록(예: AI, LLM, GPT, machine learning, Claude, Gemini, OpenAI, Anthropic 등)으로 title/본문을 매칭해 AI 관련 스토리만 남긴다 | 필수 |
| FR-5 | 기술 키워드 목록(model, benchmark, open source, research, paper 등)과 비즈니스 키워드 목록(funding, acquisition, valuation, IPO, revenue, regulation 등)으로 각 스토리를 "기술" 또는 "비즈니스" 카테고리로 분류한다. 두 키워드셋에 모두 매칭되면 매칭 개수가 더 많은 카테고리로 분류하고, 동률이면 "기술"로 분류한다 | 필수 |
| FR-6 | 발송 이력 DB에 이미 존재하는 item id는 후보에서 제외한다 | 필수 |
| FR-7 | 카테고리별로 Hot 점수(`points + comments * 가중치`) 기준 정렬 후 상위 N건(기본 15건)을 후보 풀로 추린다 | 필수 |
| FR-8 | 카테고리별 후보 풀(제목, URL, 포인트, 댓글수, 게시 시각)을 Claude API에 1회 전달해 카테고리별 최종 Top5(또는 후보가 5건 미만이면 있는 만큼)를 선정하고, 각 항목의 한국어 제목과 한줄 요약을 구조화된 출력(JSON 스키마)으로 받는다 | 필수 |
| FR-9 | Claude 응답을 텔레그램 메시지로 포맷팅한다: 카테고리 제목, 순번, 한국어 제목, 한줄 요약, 원문 링크, 포인트/댓글수를 포함하며 4096자 제한에 맞춰 필요 시 여러 메시지로 분할 발송한다 | 필수 |
| FR-10 | 카테고리 후보가 5건 미만이면 해당 섹션 상단에 부족 안내 문구를 추가하고, 0건이면 "이번 기간 동안 발견된 소식이 없습니다"로 표시한다 (실패로 취급하지 않음) | 필수 |
| FR-11 | 발송에 성공하면 이번에 선정된 모든 item id와 발송 시각을 발송 이력 DB에 기록한다 | 필수 |
| FR-12 | 각 단계(HN 검색 건수, AI 필터 통과 건수, 카테고리별 후보 풀 크기, 최종 선정 건수, 텔레그램 발송 성공 여부)를 `logging` 모듈로 기록한다 | 필수 |
| FR-13 | HN Algolia API 호출이 타임아웃/연결 오류 또는 5xx 응답으로 실패하면 최대 3회까지(1회 요청 + 2회 재시도) 지수 백오프(1초, 2초)로 재시도하고, 그래도 실패하면 완전 실패로 처리한다. 4xx 응답은 재시도해도 결과가 같으므로 즉시 실패 처리한다 | 필수 |
| FR-14 | 텔레그램 발송과 발송 이력 기록이 끝난 뒤, 텔레그램용으로 포맷팅한 것과 동일한 메시지를 `kakaotalk_sender` 스킬을 서브프로세스로 호출해 지정 대화방("금칠", "화공97", "고대97")에도 발송한다. `CLAUDE.md` 3.3(스킬 격리)에 따라 `kakaotalk_sender`의 코드를 직접 import하지 않는다 | 필수 |
| FR-15 | FR-14의 카카오톡 발송은 best-effort로 취급한다: 실패해도(0이 아닌 종료 코드) 에러 로그만 남기고 `run()`의 종료 코드나 텔레그램 발송/발송 이력 기록 결과에는 영향을 주지 않는다 — macOS UI 자동화 기반이라 텔레그램 API 호출보다 실패 가능성이 구조적으로 높다고 판단했기 때문 | 필수 |

## 4. 비기능 요구사항
- **성능**: 하루 1회(daily) 또는 주 1회(weekly) 실행 기준이며 처리 시간 제약은 없다. HN
  Algolia API 호출에는 타임아웃 45초(FR-13 재시도 백오프 포함 시 최악의 경우 키워드 1개당
  최대 약 1분 30초), Claude API와 텔레그램 API 호출에는 각각 타임아웃 30초를 두고, 초과 시
  해당 단계는 실패로 간주한다.
- **신뢰성**: HN Algolia API 호출만 최대 3회까지 지수 백오프로 재시도한다(FR-13) — 실제
  운영 중 HN API 응답 지연으로 스킬 전체가 실패한 사례가 있어, 단발성 지연에 대한 내성을
  높이기 위해 도입했다. Claude API와 텔레그램 발송은 이번 버전에서도 재시도하지 않는다
  (각 1회 시도, 실패 시 즉시 완전 실패로 처리하고 로그에 원인을 남긴다) — Claude 재시도는
  중복 과금/응답 일관성 문제가, 텔레그램 재시도는 중복 발송 위험이 있어 범위에서 제외했다.
  두 API에 대한 재시도 정책이 필요해지면 이후 버전에서 별도로 다룬다. 카카오톡 발송
  (FR-14)은 재시도하지 않으며 실패해도 완전 실패로 취급하지 않는다(FR-15) — 텔레그램이
  검증된 주 발송 채널이고, 카카오톡은 UI 자동화 기반이라 구조적으로 실패 가능성이 더
  높은 보조 채널이라고 판단했기 때문이다.
- **보안**: `TELEGRAM_BOT_TOKEN`, `ANTHROPIC_API_KEY`는 `.env`로만 로드하며 로그에 원문을
  남기지 않는다.
- **로깅/모니터링**: 표준 `logging` 모듈로 실행 시작/모드/각 단계 결과/종료 코드를 기록해
  Hermes 또는 스케줄러가 실행 로그로 성공/실패를 판단할 수 있게 한다. `print`는 사용하지
  않는다 (`CLAUDE.md` 3.4).
- **AI 사용 최소화**: 후보 선별·분류·중복 제거는 전부 규칙 기반 로직으로 처리하며, Claude API
  호출은 실행당 정확히 1회(최종 랭킹 + 한국어 요약 생성)로 제한한다.

## 5. 입출력 명세
### 5.1 입력
| 항목 | 타입 | 필수 여부 | 유효성 규칙 | 설명 |
|---|---|---|---|---|
| `--mode` | 커맨드라인 인자 | 필수 | `daily` 또는 `weekly`만 허용 | 검색 기간(24시간/7일)을 결정 |
| `TELEGRAM_BOT_TOKEN` | 환경변수 | 필수 | 비어있지 않은 문자열 | 텔레그램 발송용 봇 토큰 |
| `TELEGRAM_CHAT_ID` | 환경변수 | 필수 | 비어있지 않은 문자열 | 결과를 받을 채팅 ID |
| `ANTHROPIC_API_KEY` | 환경변수 | 필수 | 비어있지 않은 문자열 | 최종 랭킹/요약 생성용 Claude API 키 |
| 발송 이력 DB 경로 | 코드 상수 | 선택 | 존재하지 않으면 최초 실행 시 스키마 생성 | 기본값 `skills/ai_news_telegram/data/sent_items.db` |

### 5.2 출력
| 항목 | 타입 | 설명 |
|---|---|---|
| 텔레그램 메시지 | 텍스트 메시지 1건 이상 | 기술/비즈니스 Top5 요약, 부족/0건 시 안내 문구 포함 |
| 발송 이력 DB 반영 | SQLite insert | 이번에 발송된 item id, 카테고리, 발송 시각 기록 |
| 실행 로그 | 로그 파일/표준출력 | 단계별 건수, 성공/실패, 텔레그램 발송 결과 |
| 종료 코드 | 정수 | 완전 실패 시 0이 아닌 값, 그 외에는 0 |

## 6. 상태/흐름
```
[시작]
  └ --mode 검증, .env 로드 → 값 누락/잘못된 mode → 완전 실패로 종료 (FR-1, FR-2)
[검색] HN Algolia API, 기간 필터(daily=24h / weekly=7d) → 실패 시 완전 실패로 종료
[필터링] AI 키워드 매칭 (FR-4) → 발송 이력 DB에 있는 item 제외 (FR-6)
[분류] 기술/비즈니스 키워드 매칭으로 카테고리 분류 (FR-5)
[점수화] Hot 점수 계산 후 카테고리별 상위 N건 후보 풀 구성 (FR-7)
[랭킹+요약] Claude API 1회 호출 → 카테고리별 최종 Top5 + 한국어 요약 (FR-8)
  └ 호출 실패/응답 파싱 실패 → 완전 실패로 종료
[포맷팅] 텔레그램 메시지 구성, 부족/0건 안내 문구 반영 (FR-9, FR-10)
[발송] 텔레그램 전송
  └ 실패 → 완전 실패로 종료 (발송 이력 DB에는 기록하지 않음)
  └ 성공 → 발송 이력 DB에 item id 기록 (FR-11)
[카카오톡 발송] kakaotalk_sender 서브프로세스 호출(금칠/화공97/고대97) (FR-14)
  └ 실패해도 완전 실패로 취급하지 않음, 에러 로그만 남기고 계속 진행 (FR-15)
[종료] 로그 기록 후 종료 코드 반환
```

## 7. 예외 처리
| 상황 | 처리 방식 |
|---|---|
| `.env` 필수 값 누락 | 실행 시작 전 에러 로그 남기고 0이 아닌 종료 코드로 즉시 종료 |
| `--mode` 인자 누락/잘못된 값 | 실행 시작 전 에러 로그 남기고 0이 아닌 종료 코드로 즉시 종료 |
| HN Algolia API 호출 실패/타임아웃(연결 오류, 타임아웃, 5xx) | 1초·2초 간격으로 최대 2회 재시도(총 3회 시도), 재시도 시마다 경고 로그. 3회 모두 실패하면 완전 실패로 처리, 에러 로그 남기고 0이 아닌 종료 코드로 종료 (FR-13) |
| HN Algolia API 4xx 응답(잘못된 요청 등) | 재시도해도 결과가 같으므로 즉시 완전 실패로 처리, 에러 로그 남기고 0이 아닌 종료 코드로 종료 |
| 검색 결과는 성공했으나 AI 필터 통과 건수 0건 | 완전 실패로 보지 않고, 두 카테고리 모두 "이번 기간 동안 발견된 소식이 없습니다" 메시지로 발송 진행 |
| 카테고리별 후보 풀이 5건 미만 | 완전 실패로 보지 않고, 있는 만큼 Claude에 전달해 부족 안내 문구와 함께 발송 (FR-10) |
| Claude API 호출 실패/타임아웃 | 완전 실패로 처리, 에러 로그 남기고 0이 아닌 종료 코드로 종료 |
| Claude 응답이 지정한 JSON 스키마와 불일치 | 완전 실패로 처리, 원본 응답을 로그에 남겨 프롬프트 보완 근거로 사용하고 0이 아닌 종료 코드로 종료 |
| 발송 이력 DB 파일 쓰기 실패(잠금 등) | 텔레그램 발송은 이미 완료된 상태로 유지, 에러 로그 남기고 0이 아닌 종료 코드로 종료 |
| 텔레그램 전송 실패 (네트워크/토큰 오류 등) | 발송 이력 DB에는 기록하지 않음, 에러 로그 남긴 뒤 0이 아닌 종료 코드로 종료 |
| 카카오톡 발송 실패(`kakaotalk_sender` 0이 아닌 종료 코드, 타임아웃, 예외 등) | 완전 실패로 취급하지 않음(FR-15) — 에러 로그만 남기고 `run()`은 그대로 진행, 텔레그램 발송/발송 이력 기록 결과는 그대로 유지 |

## 8. 외부 의존성
- **외부 API/서비스**: Hacker News Algolia Search API(`hn.algolia.com`, 인증 불필요), Anthropic
  Messages API(구조화 출력, 실행당 1회 호출), Telegram Bot API
- **로컬 스킬 연동**: `kakaotalk_sender`(`skills/kakaotalk_sender/src/main.py`)를
  서브프로세스로 호출한다(`CLAUDE.md` 3.3 스킬 격리 원칙에 따라 코드는 import하지 않음).
  대상 대화방은 "금칠", "화공97", "고대97" 3곳으로 고정한다(FR-14). `kakaotalk_sender`
  자체의 macOS/`cliclick`/카카오톡 로그인 요구사항은 그대로 적용된다
  (`skills/kakaotalk_sender/docs/SRS.md` 참고)
- **인증 방식 및 필요한 자격 증명**: `ANTHROPIC_API_KEY`(Claude API), `TELEGRAM_BOT_TOKEN` +
  `TELEGRAM_CHAT_ID`(텔레그램). HN Algolia API는 인증 불필요
- **Python 패키지(초안)**: `requests`, `anthropic`, `python-dotenv`, `sqlite3`(표준 라이브러리).
  정확한 버전은 골격 작성 단계에서 확정
- **HN Algolia API 스펙 확인 결과 (Phase 0에서 실제 호출로 검증 완료)**:
  - 엔드포인트: `https://hn.algolia.com/api/v1/search_by_date` — `search`(관련도순)가 아닌
    `search_by_date`를 사용해야 기간 필터링 후 직접 Hot 점수로 재정렬하는 이번 설계에 맞다.
  - 주요 파라미터: `query`(검색어), `tags=story`(스토리만, 댓글 제외), `numericFilters=created_at_i>{unix_timestamp}`
    (기간 필터), `hitsPerPage`(최대 결과 수)
  - 응답의 `hits[]` 항목에서 사용할 필드: `objectID`(발송 이력 dedup 키), `title`, `url`(Show HN/Ask HN
    등 자체 게시물은 없을 수 있음 — 없으면 `https://news.ycombinator.com/item?id={objectID}`로 대체),
    `story_text`(자체 게시물 본문, AI 키워드 매칭에 함께 사용), `points`, `num_comments`, `created_at_i`
  - `query`에 여러 단어를 한 번에 넣으면 AND(모두 포함)로 동작해 AI_KEYWORDS를 한 번에 묶어
    보낼 수 없다는 것도 실제 호출로 확인, 키워드별 개별 검색 후 objectID로 병합하는 방식을 채택함
  - **재시도/타임아웃 (운영 중 실제 타임아웃 장애 발생 후 추가, FR-13)**: 타임아웃을 30초→45초로
    늘리고, 연결 오류/타임아웃/5xx에 한해 최대 3회 시도(1초·2초 백오프)로 재시도한다. 4xx는
    재시도 대상에서 제외한다(같은 요청을 반복해도 결과가 바뀌지 않음)
- **Claude 구조화 출력(FR-8) 검증 결과 (Phase 2에서 실제 호출로 검증 완료)**:
  - `output_config.format.json_schema`에서 array 타입에 `maxItems`를 걸면 400 에러
    (`property 'maxItems' is not supported`)가 발생해 스키마로는 "최대 5개" 제약을 걸 수 없다.
    프롬프트로 지시했지만 실제로 6개를 반환한 사례가 있어, 응답을 받은 뒤 애플리케이션
    코드에서 카테고리별 상위 5건으로 다시 자른다.
  - 인증 불필요, 별도 API 키 없음. rate limit 관련 에러 응답은 이번 확인 과정에서 발생하지 않음
    (daily/weekly 각 1회 호출이라 영향 적을 것으로 판단)

## 9. 테스트 시나리오
| 시나리오 | 입력 | 기대 결과 |
|---|---|---|
| 정상 케이스 (daily, 양 카테고리 5건 이상) | `--mode daily`, 두 카테고리 모두 후보 15건 이상 | 기술/비즈니스 각 Top5 발송, 발송 이력 DB에 10건 기록, 종료 코드 0 |
| 정상 케이스 (weekly) | `--mode weekly`, 7일치 검색 성공 | 7일 기준으로 정상 검색·발송, 종료 코드 0 |
| 한 카테고리 후보 부족 | 비즈니스 후보 3건뿐 | 기술은 Top5, 비즈니스는 3건 + 부족 안내 문구 포함해 발송, 종료 코드 0 |
| 한 카테고리 후보 0건 | 비즈니스 후보 0건 | 비즈니스 섹션은 "발견된 소식이 없습니다"로 표시, 기술 섹션은 정상 발송, 종료 코드 0 |
| 중복 발송 방지 | 이전 실행에서 이미 보낸 item이 이번 검색 결과에도 포함 | 해당 item은 후보에서 제외되고 나머지로 Top5 구성 |
| `--mode` 잘못된 값 | `--mode monthly` | 실행 시작 전 종료, 에러 로그, 종료 코드 0이 아님 |
| 환경변수 누락 | `ANTHROPIC_API_KEY` 미설정 | 실행 시작 전 종료, 에러 로그, 종료 코드 0이 아님 |
| HN API 일시적 실패 후 회복 | 1~2번째 시도는 타임아웃, 3번째 시도에서 성공 | 재시도 경고 로그 남기고 정상 진행, 종료 코드 0 |
| HN API 지속적 실패 | 3회 모두 타임아웃 | 완전 실패, 에러 로그, 텔레그램 미발송, 종료 코드 0이 아님 |
| HN API 4xx 응답 | HN Algolia API가 400 반환 | 재시도 없이 즉시 완전 실패, 에러 로그, 종료 코드 0이 아님 |
| Claude 응답 파싱 실패 | Claude가 지정 JSON 스키마와 다른 응답 반환 | 완전 실패, 원본 응답 로그, 종료 코드 0이 아님 |
| 텔레그램 발송 실패 | 유효하지 않은 `TELEGRAM_BOT_TOKEN` | 발송 이력 DB 미기록, 에러 로그, 종료 코드 0이 아님 |
| 카카오톡 발송 성공 | 텔레그램 발송/발송 이력 기록 모두 성공, `kakaotalk_sender`도 종료 코드 0 | 카카오톡 발송 성공 로그, 종료 코드 0 |
| 카카오톡 발송 실패(방 이름 오류 등) | `kakaotalk_sender`가 0이 아닌 종료 코드 반환 | 에러 로그만 남기고 완전 실패로 취급하지 않음, 종료 코드는 텔레그램/DB 결과 그대로 0 |

## 10. 제약사항 / 비범위
- 뉴스 소스는 Hacker News 1곳만 사용한다 (PRD 7절).
- 정기 실행(스케줄링) 로직은 포함하지 않는다 — Hermes 또는 OS 스케줄러가 담당 (PRD 7절).
- Hot 점수식과 카테고리 분류 키워드 목록의 자동 학습/조정 기능은 포함하지 않는다.
- 재시도 정책은 HN Algolia API 호출에만 적용한다(FR-13). Claude API 호출과 텔레그램 발송은
  이번 버전에서도 재시도하지 않는다(4절 참고).
- 사용자가 특정 글을 발송 이력에서 수동으로 추가/제외하는 관리 기능은 포함하지 않는다.
- 카카오톡 발송 대상 방("금칠", "화공97", "고대97")은 코드 상수로 고정한다 — 이번
  버전에서는 CLI 인자 등으로 실행 시점에 바꾸는 기능을 제공하지 않는다(FR-14).
- 카카오톡 발송은 재시도하지 않으며(FR-15), `kakaotalk_sender` 자체의 제약사항(macOS
  전용, 화면 잠금 상태 미검증 등, `skills/kakaotalk_sender/docs/SRS.md` 10절)을 그대로
  물려받는다.
