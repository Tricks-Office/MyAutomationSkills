# Changelog — kakaotalk_sender

## [0.1.1]
- `ai_news_telegram` 연동 첫 실사용 중, 여러 방을 순차 처리할 때 이전 방의 대화창을
  닫지 않아 다음 방 검색어가 그 창의 메시지 입력창에 잘못 입력되는 사고 확인 후 수정 —
  방 처리 후(성공/실패 무관) 메인 목록 창만 남기고 나머지 창을 닫도록 변경(FR-17).
  같은 방을 연속 두 번 처리하는 회귀 테스트로 실제 환경 재검증 완료
- 전송 검증(FR-12) 타임아웃을 `OSASCRIPT_TIMEOUT_SECONDS`(15→30초)/
  `SEND_VERIFY_TIMEOUT_SECONDS`(5→35초)로 상향
- **알려진 문제(미해결)**: 위 타임아웃 상향에도 불구하고, 실제 리포트 수준(약 1,800자)
  메시지 3건을 실제 대화방 3곳에 보낸 결과 **전송 자체는 매번 성공**했지만 전송 검증
  단계는 매번 타임아웃으로 실패 보고됨을 확인했다. 즉 이 버전은 긴 메시지에서
  `kakaotalk_sender`가 "실패"를 보고해도 실제로는 도착했을 가능성이 높다 — 로그만으로
  성공 여부를 신뢰할 수 없다. 근본 원인 조사 및 검증 로직 재설계는 다음 패치 과제로
  SRS 10절에 기록
- 스모크 테스트 2개 추가

## [0.1.0]
- macOS에 설치되어 로그인된 카카오톡 데스크톱 앱을 `cliclick`(실제 클릭/키 이벤트) +
  System Events(AppleScript)로 조작해 지정 대화방(들)에 텍스트 메시지를 전송하는 기능 구현
- 검색으로 대화방을 정확히 일치하는 이름으로 찾고, 더블클릭으로 연 뒤 열린 창 이름을
  재확인해 다른 대화방이 잘못 열리는 오동작을 방지
- 메시지는 클립보드(UTF-8 인코딩 명시)로 설정 후 붙여넣고, 붙여넣은 내용을 클립보드
  왕복으로 재확인한 뒤에만 전송 버튼을 클릭
- 전송 후 대화 내역에서 보낸 텍스트를 직접 읽어 전송 검증(입력창이 비워졌는지 여부는
  신뢰할 수 없어 판단 근거로 쓰지 않음)
- 여러 `--room`을 순차 처리하고 방별 성공/실패를 집계, 하나라도 실패하면 0이 아닌
  종료 코드 반환
- 마우스 클릭/키 입력 직전마다 시스템 frontmost 프로세스가 KakaoTalk인지 확인하는
  안전장치 적용 — 실제 검증 중 다른 앱으로 키 입력이 새는 오동작이 재현되어 필수로 채택
- 앱 미설치/Accessibility 권한 거부/로그인 안 됨(타임아웃)을 구분되는 예외로 분류해
  명확한 안내 메시지 제공(화면 잠금 상태는 미검증)
- 실제 카카오톡 계정·대화방으로 정상 케이스/존재하지 않는 방/부분 실패 케이스 end-to-end
  검증 완료
- 스모크 테스트 18개 추가(`tests/test_main.py`), macOS UI 자동화 호출은 전부 mock 처리
