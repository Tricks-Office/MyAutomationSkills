## 1. 개요
이 컴퓨터(macOS)에 설치되어 이미 로그인되어 있는 카카오톡 데스크톱 앱을, macOS
System Events(AppleScript UI 자동화)로 조작해 지정한 대화방(들)에 텍스트 메시지를
전송하는 범용 스킬이다. 카카오톡 계정의 별도 인증이나 세션 토큰 추출, 비공식
API/프로토콜 연동을 전혀 사용하지 않고, 이미 로그인된 앱 화면을 사람이 클릭·타이핑하는
것과 동일한 방식으로 조작한다(설계 배경은 8절 참고).

이 스킬은 특정 리포트(예: `ai_news_telegram`)에 종속되지 않는 범용 "카카오톡 발송기"로
설계한다. 다른 스킬은 이 스킬의 코드를 import하지 않고, `CLAUDE.md` 3.3의 스킬 격리
원칙에 따라 `python skills/kakaotalk_sender/src/main.py ...`를 서브프로세스로 호출해
재사용한다.

## 2. 용어 정의
| 용어 | 정의 |
|---|---|
| 대상 대화방 | `--room` 인자로 지정한, 메시지를 받을 카카오톡 채팅방 이름(정확히 일치해야 함) |
| 전송 검증 | 메시지 전송(Return) 직후, 접근성 트리에서 읽어낸 값으로 실제 전송 여부를 확인하는 절차 (정확한 방식은 4절 Phase 0에서 확정, 10절 참고) |
| 완전 실패 | 앱 활성화/로그인 확인 단계에서 실패해 어떤 방에도 전송을 시도조차 못한 상태 |
| 부분 실패 | 하나 이상의 방은 전송에 성공했지만, 다른 하나 이상의 방은 실패한 상태 (완전 실패와 구분) |

## 3. 기능 요구사항
| ID | 요구사항 설명 | 우선순위(필수/선택) |
|---|---|---|
| FR-1 | CLI 인자로 `--room`(반복 가능, 1개 이상 필수)과 `--message`(문자열) 또는 `--message-file`(파일 경로) 중 정확히 하나를 받는다. `--room`이 없거나, `--message`/`--message-file`이 둘 다 없거나 둘 다 있으면 실행 시작 전 실패 처리한다 | 필수 |
| FR-2 | 실행 시작 시 `sys.platform`이 macOS(`darwin`)가 아니면 즉시 실패 처리한다 | 필수 |
| FR-3 | KakaoTalk.app을 활성화(activate)한 뒤, 지정 타임아웃(기본 10초) 내에 메인 창(채팅방 목록)이 접근성 트리에 나타나는지 확인한다. 나타나지 않으면(앱 미설치/로그인 안 됨/응답 없음) 완전 실패로 처리한다 | 필수 |
| FR-4 | `--room`으로 지정된 각 대화방에 대해 순차적으로(동시 실행 없이) 검색 기능으로 이름을 정확히 일치시켜 연다. 일치하는 방이 0개이거나 2개 이상(중복 이름)이면 그 방은 실패로 기록하고 다음 방으로 진행한다(다른 방을 임의로 추측해 열지 않는다) | 필수 |
| FR-5 | 메시지 텍스트는 개별 키 입력(keystroke) 시뮬레이션 대신 시스템 클립보드에 설정한 뒤 붙여넣기(Cmd+V)로 입력창에 삽입한다 — 한글/이모지/멀티라인 텍스트를 키 입력으로 재현할 때 발생하는 인코딩·타이밍 오류를 피하기 위함 | 필수 |
| FR-6 | 입력창에 메시지가 삽입된 뒤 Return으로 전송하고, 전송 검증(2절 용어 정의, 정확한 방식은 Phase 0에서 확정)을 수행한다. 검증에 실패하거나 타임아웃되면 그 방은 실패로 기록한다 | 필수 |
| FR-7 | 방 단위 처리는 자동 재시도하지 않는다(1회 시도, 성공/실패만 기록) — 자동 재시도가 오히려 중복 전송 위험을 키운다고 판단했기 때문. 재시도가 필요하면 호출자가 실패한 방만 골라 다시 실행한다 | 필수 |
| FR-8 | 모든 대상 방 처리가 끝난 뒤 방별 성공/실패를 요약해 로그로 남긴다. 하나라도 실패하면(부분 실패 포함) 종료 코드를 0이 아닌 값으로 반환한다 | 필수 |
| FR-9 | 메시지 원문 전체는 로그에 남기지 않는다 — 방 이름, 메시지 길이, 성공/실패 여부만 기록한다(개인 대화 내용이 로그 파일에 평문으로 남는 것을 방지하기 위한 설계 판단) | 필수 |
| FR-10 | System Events 호출이 손쉬운 사용(Accessibility) 권한 거부로 실패하면, 재시도 없이 명확한 에러 메시지(권한 부여 방법 안내 포함)와 함께 완전 실패로 처리한다 | 필수 |

## 4. 비기능 요구사항
- **성능**: 방 개수만큼 순차 처리하며, UI 반응 대기가 포함돼 방 1개당 수 초~10여 초가
  소요될 수 있다. 전체 처리 시간에 대한 상한은 두지 않는다(자동화 특성상 동시 처리가
  오히려 오동작 위험을 높이므로 의도적으로 순차 처리한다).
- **신뢰성**: 자동 재시도를 두지 않는다(FR-7) — 오발송/중복 전송 위험이 재시도로 얻는
  이득보다 크다고 판단했다. 대신 전송 후 검증(FR-6)으로 "실패했는데 성공으로 오인하는"
  상황을 최소화한다. 다만 카카오톡 채팅 버블이 접근성 트리에 텍스트로 노출되지 않을 경우
  검증 방식 자체를 약화해야 할 수 있다 — 이 불확실성은 10절과 Implementation Plan
  4절에 명시한다.
- **보안**: 별도로 저장하거나 다루는 자격 증명이 없다(기존 로그인 세션을 그대로
  사용하므로 비밀번호/토큰/세션 값을 코드가 직접 다루지 않는다). 메시지 원문은
  로그에 남기지 않는다(FR-9).
- **로깅/모니터링**: 표준 `logging` 모듈로 앱 활성화 결과, 방별 검색/전송/검증 결과,
  최종 요약을 기록해 Hermes가 실행 로그로 성공/부분 실패/완전 실패를 판단할 수 있게
  한다. `print`는 사용하지 않는다(`CLAUDE.md` 3.4).
- **플랫폼 제약**: macOS 전용. KakaoTalk 데스크톱 앱이 설치되어 있고 이미 로그인된
  상태여야 하며, 화면 잠금이 해제된 상태에서 실행해야 한다. 실행 프로세스(터미널 등)에
  손쉬운 사용(Accessibility) 권한이 부여되어 있어야 한다.

## 5. 입출력 명세
### 5.1 입력
| 항목 | 타입 | 필수 여부 | 유효성 규칙 | 설명 |
|---|---|---|---|---|
| `--room` | 커맨드라인 인자(반복 가능) | 필수(최소 1개) | 빈 문자열 불가 | 메시지를 보낼 대화방 이름(정확히 일치) |
| `--message` | 커맨드라인 인자 | `--message-file`과 상호배타, 둘 중 하나 필수 | 빈 문자열 불가 | 전송할 메시지 본문 |
| `--message-file` | 커맨드라인 인자(파일 경로) | `--message`와 상호배타, 둘 중 하나 필수 | 파일이 존재하고 읽기 가능해야 함 | 전송할 메시지 본문을 담은 텍스트 파일(긴 리포트 등) |

### 5.2 출력
| 항목 | 타입 | 설명 |
|---|---|---|
| 실행 로그 | 로그(표준출력/로그 파일) | 앱 활성화 결과, 방별 성공/실패, 실패 사유(방 못 찾음/검증 실패/권한 없음 등) |
| 종료 코드 | 정수 | 전체 성공 시 0, 완전 실패 또는 부분 실패 시 0이 아닌 값 |

이번 버전에서는 DB나 파일 등 영속 상태를 남기지 않는다(무상태 실행, 10절 참고).

## 6. 상태/흐름
```
[시작] 인자 검증(--room, --message/--message-file 배타) → 실패 시 완전 실패로 종료 (FR-1)
  └ macOS 여부 확인 → 아니면 완전 실패로 종료 (FR-2)
[앱 활성화] KakaoTalk.app activate → 타임아웃 내 메인 창 확인
  └ 실패(미설치/로그인 안 됨/권한 없음) → 완전 실패로 종료 (FR-3, FR-10)
[방 루프] --room 목록을 순차 처리 (동시 실행 없음)
  ├ [검색] 대화방 이름 정확히 일치하는 방 찾기
  │   └ 0개/2개 이상 → 이 방은 실패로 기록, 다음 방으로 (FR-4)
  ├ [입력] 클립보드 설정 → 입력창에 붙여넣기 (FR-5)
  ├ [전송] Return → 전송 검증 수행
  │   └ 검증 실패/타임아웃 → 이 방은 실패로 기록, 다음 방으로 (FR-6)
  └ 성공 → 이 방은 성공으로 기록
[집계] 방별 결과 요약 로그 출력 (FR-8, FR-9)
[종료] 하나라도 실패 → 0이 아닌 종료 코드, 전체 성공 → 종료 코드 0
```

## 7. 예외 처리
| 상황 | 처리 방식 |
|---|---|
| `--room` 누락 | 실행 시작 전 에러 로그, 0이 아닌 종료 코드로 즉시 종료 |
| `--message`/`--message-file` 둘 다 없거나 둘 다 있음 | 실행 시작 전 에러 로그, 0이 아닌 종료 코드로 즉시 종료 |
| `--message-file` 경로가 존재하지 않거나 읽기 실패 | 실행 시작 전 에러 로그, 0이 아닌 종료 코드로 즉시 종료 |
| macOS가 아닌 환경에서 실행 | 실행 시작 전 에러 로그, 0이 아닌 종료 코드로 즉시 종료 |
| KakaoTalk.app이 설치되어 있지 않음 | 완전 실패, 에러 로그(설치 필요 안내), 0이 아닌 종료 코드 |
| 앱은 실행되나 로그인 화면(메인 채팅 목록 없음) | 완전 실패, 에러 로그(수동 로그인 필요 안내), 0이 아닌 종료 코드 |
| 손쉬운 사용(Accessibility) 권한 거부 | 완전 실패, 에러 로그(권한 부여 경로 안내), 0이 아닌 종료 코드 (FR-10) |
| 화면 잠금 상태 | UI 자동화 실패로 감지되는 시점에 해당 단계 실패 처리, 에러 로그, 0이 아닌 종료 코드 |
| 특정 방 이름이 대화방 목록에 없음 | 그 방만 실패로 기록, 다른 방은 계속 처리 (FR-4) |
| 방 이름이 2개 이상과 일치(중복) | 그 방만 실패로 기록(임의 선택 금지), 다른 방은 계속 처리 (FR-4) |
| 전송 후 검증 실패(내용 불일치/타임아웃) | 그 방만 실패로 기록, 다른 방은 계속 처리 (FR-6) |
| 일부 방 성공, 일부 방 실패(부분 실패) | 성공한 방은 그대로 두고(재전송하지 않음), 요약 로그에 실패한 방을 명시, 0이 아닌 종료 코드로 종료 (FR-7, FR-8) |

## 8. 외부 의존성
- **외부 API/서비스**: 없음. 카카오톡 공식/비공식 API, LOCO 프로토콜, 세션 토큰 추출 등을
  전혀 사용하지 않는다 — 이미 로그인되어 실행 중인 데스크톱 앱을 macOS System Events로
  조작하는 방식만 사용한다. (이 설계는 "agent-messenger" 등 세션 토큰을 추출하는 서드파티
  패키지의 계정 정지·공급망 리스크를 피하기 위해 의도적으로 선택했다.)
- **인증 방식 및 필요한 자격 증명**: 없음. 기존 로그인 세션을 그대로 재사용하므로 비밀번호,
  토큰, API 키 등을 다루지 않는다. `.env`/`docs/ENVIRONMENT.md`에 추가할 항목 없음.
- **Python 패키지(초안)**: 표준 라이브러리만 사용(`argparse`, `logging`, `subprocess`,
  `platform`). `osascript`(macOS 내장) 호출로 AppleScript/System Events를 실행하며, 별도
  pip 패키지는 필요하지 않을 것으로 예상 — Phase 0에서 확정한다.
- **macOS 요구사항**: 손쉬운 사용(Accessibility) 권한을 실행 프로세스(터미널 또는
  Hermes 실행 환경)에 부여해야 한다. KakaoTalk 데스크톱 앱 설치 및 로그인 필요.

## 9. 테스트 시나리오
| 시나리오 | 입력 | 기대 결과 |
|---|---|---|
| 정상 케이스(단일 방) | `--room "테스트방" --message "안녕"`, 앱 정상/로그인됨 | 방 열림→붙여넣기→전송→검증 성공, 종료 코드 0 |
| 정상 케이스(여러 방) | `--room "방A" --room "방B" --message "..."` | 두 방 모두 순차 전송 성공, 종료 코드 0 |
| `--message-file`로 긴 리포트 전송 | `--message-file report.txt`(멀티라인) | 줄바꿈 포함 그대로 전송, 종료 코드 0 |
| 인자 오류(둘 다 없음) | `--room "방A"`만 지정 | 실행 시작 전 종료, 에러 로그, 종료 코드 0이 아님 |
| 인자 오류(둘 다 지정) | `--message "a" --message-file f.txt` 동시 지정 | 실행 시작 전 종료, 에러 로그, 종료 코드 0이 아님 |
| 존재하지 않는 방 | `--room "없는방"` | 해당 방 실패로 기록, 종료 코드 0이 아님 |
| 방 이름 중복 | 동일 이름의 채팅방이 2개 이상 열려 있음 | 해당 방 실패로 기록(임의 선택 없음), 종료 코드 0이 아님 |
| 부분 실패 | `--room "방A" --room "없는방"` | 방A는 성공, "없는방"은 실패로 요약 로그에 표시, 종료 코드 0이 아님 |
| 앱 로그인 안 됨 | KakaoTalk.app이 로그인 화면 상태 | 완전 실패, 어떤 방도 시도하지 않음, 종료 코드 0이 아님 |
| Accessibility 권한 없음 | 손쉬운 사용 권한 미부여 상태에서 실행 | 완전 실패, 권한 안내 에러 로그, 종료 코드 0이 아님 |

실제 UI 자동화(System Events ↔ KakaoTalk.app) 부분은 macOS 환경과 로그인된 카카오톡
계정이 있어야 검증 가능하므로, `osascript` 호출 자체는 mock 처리한 스모크 테스트를
기본으로 하고, 실제 전송 확인은 수동 실행으로 별도 검증한다(`CLAUDE.md` 3.5).

## 10. 제약사항 / 비범위
- macOS 전용이며 Windows/Linux는 지원하지 않는다.
- 텍스트 메시지 전송만 지원한다. 이미지/파일/이모티콘 전송은 이번 버전 범위 밖이다.
- 메시지 수신/대화 내역 읽기 기능은 없다(발신 전용).
- 대화방 생성, 초대 등 채팅방 관리 기능은 없다. 이미 존재하는 대화방에만 보낼 수 있다.
- 자동 로그인/최초 인증 자동화는 하지 않는다. 로그인이 안 되어 있으면 완전 실패로
  처리하고, 사용자가 직접 로그인한 뒤 재실행해야 한다.
- 자동 재시도를 두지 않는다(4절, FR-7).
- 카카오톡 채팅 버블이 접근성 트리에 텍스트로 노출되지 않을 가능성이 있다 — 이 경우
  FR-6의 "전송 검증"은 정확한 내용 일치 대신 "입력창이 비워졌는지" 같은 약한 검증으로
  대체될 수 있다. 정확한 검증 방식은 Implementation Plan Phase 0의 스파이크 결과에 따라
  이 SRS를 갱신한다.
- 메시지 최대 길이 제한은 이번 버전에서 확정하지 않는다(Phase 0에서 실제 입력 가능
  길이를 확인한 뒤 필요 시 분할 전송 정책을 추가 버전에서 다룬다).
