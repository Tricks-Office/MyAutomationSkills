# PRD: marathon_finder

- 작성일: 2026-08-04
- 작성자: devjan
- 상태: 초안 (데이터 소스 확정 완료, 8. 참고)

## 1. 배경 및 목적
중국 남경(南京)시와 한국에서 열리는 5km 이상 도로 레이스(5km/10km/하프마라톤/풀코스 등) 중
현재 시점 기준으로 참가 신청이 가능한 대회를 매번 사람이 직접 검색하지 않고 자동으로
찾아서 정리해주기 위함. 찾은 대회는 데이터베이스에 누적 관리하고, 신청 가능한 대회를
텔레그램으로 요약해서 받아본다.

## 2. 트리거 조건
- 이 스킬 자체는 트리거(정기 실행) 로직을 포함하지 않는다.
- `python src/main.py`로 실행하면 그 시점 기준으로 1회 검색·저장·통보를 수행한다.
- 정기 실행(주 1회)은 이 스킬이 완성된 뒤 Hermes 또는 macOS 작업 스케줄러(cron/launchd)가
  이 스크립트를 호출하는 방식으로 별도 구성한다 (이 PRD의 범위 밖, 7. 참고).

## 3. 입력
| 항목 | 타입 | 필수 여부 | 설명 |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | 환경변수 | 필수 | 저장소 공용 `.env`에 이미 등록되어 있음 (`docs/ENVIRONMENT.md` 참고) |
| `TELEGRAM_CHAT_ID` | 환경변수 | 필수 | 결과를 받을 본인 개인 채팅의 chat_id. 저장소 공용 `.env`에 실제 값까지 등록 완료 (`docs/ENVIRONMENT.md` 참고) |
| `ANTHROPIC_API_KEY` | 환경변수 | 필수 | 중국 남경 대회 검색에 사용할 Claude API 키. 저장소 공용 `.env`에 이미 등록되어 있음 |
| DB 파일 경로 | 설정값(코드 상수) | 선택 | 기본값: 저장소 최상위 `data/marathon.db` (SQLite). 향후 "텔레그램 회신 제외 체크" 스킬도 같은 파일을 읽고 쓰므로 특정 스킬 폴더가 아닌 공용 `data/`에 둔다 (`CLAUDE.md` 2절 참고) |
| 실행 인자 | 없음 | - | 실행 시점의 날짜를 기준으로 자동 검색하며 별도 커맨드라인 인자는 받지 않는다 |

## 4. 출력
- **DB 반영**: 새로 발견한 대회는 신규 삽입, 기존에 저장된 대회는 정보 갱신(upsert). (5. 참고)
- **텔레그램 메시지**: DB 상 "현재 접수중"이며 "텔레그램 회신 제외"로 표시되지 않은 대회 목록을
  대회명 / 날짜 / 장소 / 거리(종목) / 접수 마감일 / 신청 링크로 간단히 요약해 한 번에 전송한다.
- 검색 결과가 0건이어도 "이번 실행에서 접수중인 신규 대회가 없습니다"라는 안내 메시지를 보내
  실행이 정상적으로 완료됐음을 알 수 있게 한다.

### DB 도구 및 스키마 (초안)
- **DB 엔진**: SQLite (Python 표준 `sqlite3` 모듈, 추가 설치 불필요). 서버·인증이 필요 없고
  파일 하나로 백업/이동이 되며, 이번 기능의 조회(접수중 여부, 날짜 비교, `notify_telegram`
  필터)에 SQL이 적합해 채택. ORM/클라우드 DB는 이 스킬 규모에는 과함으로 판단해 제외.
- **파일 위치**: `data/marathon.db` (저장소 최상위 공용 `data/` 폴더, `CLAUDE.md` 2절 참고)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `id` | INTEGER PK | 자동 증가 |
| `country` | TEXT | `KR` / `CN` |
| `race_name` | TEXT | 대회명 |
| `race_date` | DATE | 대회 개최일 |
| `location` | TEXT | 개최 장소(도시 등) |
| `distance_km` | TEXT | 참가 가능 종목(예: `5,10,21.0975,42.195`) |
| `registration_start` | DATE | 접수 시작일 (확인 가능한 경우) |
| `registration_end` | DATE | 접수 마감일 |
| `registration_url` | TEXT | 신청 페이지 링크 |
| `source_site` | TEXT | 정보를 가져온 출처. 한국은 `marathonmate.store`, 중국은 `claude_web_search` 고정값 |
| `notify_telegram` | BOOLEAN | 텔레그램 요약 발송 대상 여부. 기본값 `TRUE`. 별도 기능(향후 스킬)이 이 값을 `FALSE`로
  변경해 특정 대회를 회신에서 제외할 수 있도록, 이번 스킬은 이 컬럼을 두고 조회 시 참조만 한다 |
| `first_found_at` | DATETIME | 최초 수집 시각 |
| `updated_at` | DATETIME | 마지막 갱신 시각 |

## 5. 처리 흐름 (개요)
1. `.env`에서 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `ANTHROPIC_API_KEY` 로드
2. **한국**: `marathonmate.store`의 대회 일정 페이지를 크롤링(`requests` + `beautifulsoup4`)해
   대회명/날짜/장소/거리(부문)/접수 상태를 추출하고, 5km 이상 종목을 포함하며 "접수중"인
   대회만 남긴다. (8. 의존성 참고)
3. **중국(남경)**: Claude API를 `web_search` 도구와 함께 호출해 "현재 시점 기준 남경시(南京市)에서
   접수 중인 5km 이상 도로 레이스"를 질의하고, 대회명/날짜/장소/거리/접수기간/신청링크를
   포함한 JSON으로 답하도록 요청해 파싱한다. (8. 의존성 참고)
4. 두 결과를 공통 스키마로 정규화
5. `data/marathon.db`(SQLite)에 upsert (기존 대회는 `updated_at` 갱신, 신규 대회는 `notify_telegram=TRUE`로 삽입)
6. DB에서 `notify_telegram=TRUE`이고 현재 접수중인 레코드 조회
7. 텔레그램 메시지로 포맷팅 후 `TELEGRAM_CHAT_ID`로 전송
8. 실행 결과(수집 건수, 신규 건수, 발송 성공 여부)를 로그로 남긴다

## 6. 성공/실패 기준
- **성공**: 스크립트가 예외 없이 종료되고, 텔레그램 메시지가 정상 수신된다.
- **부분 실패 허용**: 한국 크롤링과 중국 Claude 검색 중 한쪽이 실패해도 다른 쪽 결과로 계속
  진행하고, 실패한 소스는 로그에 명확히 남긴다.
- **marathonmate.store 목록 페이지 단발성 지연에 대한 내성**: 목록 페이지 요청이 타임아웃/연결
  오류/5xx로 실패하면 즉시 한국 소스 실패로 보지 않고 짧은 대기 후 최대 3회까지 재시도한다
  (`ai_news_telegram`에서 겪은 것과 같은 유형의 장애 대응, 8.2절 참고). 개별 대회 상세 페이지
  요청은 이미 실패 시 목록 페이지 링크로 폴백하므로 재시도 대상이 아니다.
- **완전 실패**: 두 소스 모두 실패하거나 텔레그램 전송이 실패하면, 원인을 알 수 있는 에러 로그를
  남기고 0이 아닌 종료 코드로 종료한다 (Hermes/스케줄러가 실패를 감지할 수 있도록).
- **중국 쪽 결과 품질**: Claude 웹 검색 결과는 매 실행마다 표현/포맷이 조금씩 달라질 수 있으므로,
  100% 완전한 목록을 보장하지 않는다. 파싱 실패 시 해당 실행의 중국 결과는 0건으로 처리하고
  로그에 원본 응답을 남겨 추후 프롬프트를 보완할 수 있게 한다.

## 7. 제약사항 / 비범위
- 정기 실행(주 1회 스케줄링) 로직은 포함하지 않는다 — Hermes 또는 OS 작업 스케줄러가 담당.
- 텔레그램 회신 제외 항목을 사용자가 체크/관리하는 기능(UI 또는 별도 커맨드)은 이번 스킬의
  범위가 아니다. 이번 스킬은 DB에 `notify_telegram` 컬럼만 두고 조회 시 그 값을 참조한다.
  (제외 기능 자체는 이후 별도 PRD로 다룬다.)
- 대회 신청(결제, 개인정보 입력 등) 자동화는 포함하지 않는다. 정보 제공과 링크 안내까지만 한다.
- "남경 근방"은 남경시(江苏省 南京市) 행정구역 내 대회로 한정한다. 인접 도시(상하이/쑤저우 등)는
  포함하지 않는다.
- 남경시는 연중 대형 대회(예: 남경마라톤) 수 자체가 적어, 실행할 때마다 중국 쪽 결과가 0건이거나
  같은 대회가 반복 조회되는 경우가 정상적으로 발생할 수 있다.

### 8.2 확정된 의존성
- **한국**: `marathonmate.store` 크롤링 (`requests` + `beautifulsoup4`). 목록 페이지 요청은
  타임아웃 30초→45초로 늘리고, 연결 오류/타임아웃/5xx에 한해 최대 3회(1초·2초 백오프)까지
  재시도한다(운영 중 `ai_news_telegram`에서 겪은 응답 지연 장애에 대응해 추가, SRS FR-10).
  4xx는 재시도해도 결과가 같으므로 제외. 개별 대회 상세 페이지 요청과 Claude `web_search`
  호출은 이번에도 재시도하지 않는다(전자는 이미 폴백이 있고, 후자는 중복 과금/응답 일관성
  우려로 SRS 4절에서 의도적으로 제외).
- **중국(남경)**: Claude API(Anthropic Messages API, `web_search` 도구) 호출 — 이미 보유한
  `ANTHROPIC_API_KEY` 사용, 매 실행(주 1회)마다 1회 호출이라 비용 영향은 미미함
- **텔레그램**: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — 저장소 공용 `.env`에 실제 값까지
  등록 완료, 구현 단계에서 바로 사용 가능
- **Python 패키지(초안)**: `requests`, `beautifulsoup4`(한국 크롤링), `anthropic`(공식 SDK,
  중국 웹 검색), `python-dotenv`(환경변수 로드), `sqlite3`(표준 라이브러리, DB). 텔레그램 전송은
  Bot API를 `requests`로 직접 호출한다. 정확한 버전은 골격 작성 단계에서 확정한다.
