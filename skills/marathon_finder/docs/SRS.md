# SRS: marathon_finder

- 작성일: 2026-08-04
- 작성자: devjan
- 상태: 초안
- 관련 PRD: [`PRD.md`](./PRD.md) (배경/입출력/DB 스키마/의존성 조사 결과는 PRD가 원본이며, 이 SRS는
  구현에 필요한 요구사항을 더 세분화한다)

## 1. 개요
현재 접수 중인 5km 이상 도로 레이스(5km/10km/하프/풀코스)를 한국(`marathonmate.store` 크롤링)과
중국 남경(Claude API `web_search`)에서 각각 수집해 공용 SQLite DB(`data/marathon.db`)에 upsert하고,
발송 대상(`notify_telegram=TRUE`)이며 현재 접수중인 대회를 텔레그램으로 요약 발송한다. 같은 내용을
`kakaotalk_sender`를 통해 카카오톡 "러닝97" 방에도 보조 채널로 발송한다(FR-11, 2026-08-20 추가).
정기 실행 스케줄링, 텔레그램 회신 제외 기능(UI/커맨드), 대회 신청 자동화는 이 스킬의 범위 밖이다
(PRD 7절).

## 2. 용어 정의
| 용어 | 정의 |
|---|---|
| 접수중 | 대회 정보 상 접수 시작일이 지났고 접수 마감일이 아직 지나지 않은 상태. `registration_start`가 없으면 접수 마감일만으로 판단 |
| upsert | `country`+`race_name`+`race_date`를 기준으로 기존 레코드가 있으면 갱신, 없으면 신규 삽입 |
| notify_telegram | 해당 대회를 텔레그램 요약 발송 대상에 포함할지 여부. 이 스킬은 신규 삽입 시 `TRUE`로 설정하고 조회 시 참조만 하며, `FALSE`로 바꾸는 것은 별도 스킬의 책임 (PRD 7절) |
| 부분 실패 | 한국/중국 두 소스 중 한쪽만 실패한 상태. 나머지 한쪽 결과로 계속 진행 |
| 완전 실패 | 두 소스가 모두 실패했거나, 결과 수집에는 성공했으나 텔레그램 전송이 실패한 상태. 카카오톡(보조 채널) 발송 실패는 포함하지 않는다(FR-11) |

## 3. 기능 요구사항
| ID | 요구사항 설명 | 우선순위 |
|---|---|---|
| FR-1 | `.env`에서 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `ANTHROPIC_API_KEY`를 로드하고, 하나라도 없으면 실행 시작 전에 실패 처리한다 | 필수 |
| FR-2 | `marathonmate.store`의 대회 일정 페이지를 크롤링해 대회명/날짜/장소/거리(부문)/접수 상태를 추출하고, 5km 이상 종목을 하나라도 포함하며 접수중인 대회만 남긴다 | 필수 |
| FR-3 | Claude API를 `web_search` 도구와 함께 호출해 남경시(江苏省 南京市) 행정구역 내에서 현재 접수중인 5km 이상 도로 레이스를 질의하고, 대회명/날짜/장소/거리/접수기간/신청링크를 포함한 JSON으로 응답받아 파싱한다 | 필수 |
| FR-4 | 한국/중국 결과를 PRD 4절의 공통 스키마(country, race_name, race_date, location, distance_km, registration_start, registration_end, registration_url, source_site)로 정규화한다 | 필수 |
| FR-5 | 정규화된 레코드를 `data/marathon.db`에 upsert한다. 신규 레코드는 `notify_telegram=TRUE`, `first_found_at`을 현재 시각으로 설정하고, 기존 레코드는 `updated_at`만 갱신하며 `notify_telegram` 값은 건드리지 않는다 | 필수 |
| FR-6 | DB에서 `notify_telegram=TRUE`이고 현재 접수중인 레코드를 조회해 대회명/날짜/장소/거리/접수 마감일/신청 링크 형식으로 텔레그램 메시지를 구성한다 | 필수 |
| FR-7 | 조회 결과가 0건이면 "이번 실행에서 접수중인 신규 대회가 없습니다" 안내 메시지를 발송한다 | 필수 |
| FR-8 | 각 단계(한국 수집 건수, 중국 수집 건수, 신규/갱신 건수, 텔레그램 발송 성공 여부)를 `logging` 모듈로 기록한다 | 필수 |
| FR-9 | 한국 또는 중국 수집이 실패해도 나머지 한쪽 결과로 처리를 계속 진행한다 (부분 실패 허용) | 필수 |
| FR-10 | `marathonmate.store` 목록 페이지 요청이 타임아웃/연결 오류 또는 5xx 응답으로 실패하면 최대 3회까지(1회 요청 + 2회 재시도) 지수 백오프(1초, 2초)로 재시도하고, 그래도 실패하면 한국 소스 실패로 처리한다. 4xx 응답은 재시도해도 결과가 같으므로 즉시 실패 처리한다. 개별 대회 상세 페이지 요청은 대상이 아니다(이미 실패 시 목록 페이지 링크로 폴백) | 필수 |
| FR-11 | 텔레그램 발송(FR-6/FR-7)에 성공한 뒤, 동일한 메시지를 `kakaotalk_sender`를 통해 카카오톡 "러닝97" 방에도 서브프로세스로 전송한다(2026-08-20 추가, `ai_news_telegram`과 동일 패턴). `CLAUDE.md` 3.3에 따라 `kakaotalk_sender`의 코드를 직접 import하지 않는다. 이 발송은 best-effort로, 실패해도 예외를 밖으로 내보내지 않고 에러 로그만 남기며 텔레그램 발송 결과나 종료 코드에 영향을 주지 않는다 | 필수 |

## 4. 비기능 요구사항
- **성능**: 주 1회 실행 기준이며 처리 시간 제약은 없다. `marathonmate.store` 목록 페이지
  요청은 타임아웃 45초(FR-10 재시도 백오프 포함 시 최악의 경우 약 1분 30초), 대회 상세
  페이지 요청과 Claude `web_search` 호출은 각각 타임아웃 30초를 두고, 초과 시 해당 요청/
  소스는 실패로 간주한다.
- **신뢰성**: `marathonmate.store` 목록 페이지 요청만 최대 3회까지 지수 백오프로 재시도한다
  (FR-10) — `ai_news_telegram`에서 외부 API 응답 지연으로 스킬 전체가 실패한 사례가 있어,
  같은 유형의 단발성 지연에 대한 내성을 이 스킬에도 동일하게 적용했다. 대회 상세 페이지
  요청(이미 실패 시 폴백 있음)과 Claude `web_search` 호출, 텔레그램 발송은 이번 버전에서도
  재시도하지 않는다(각 1회 시도, 실패 시 즉시 실패 처리하고 로그에 원인을 남긴다) — Claude
  재시도는 중복 과금/응답 일관성 문제가, 텔레그램 재시도는 중복 발송 위험이 있어 범위에서
  제외했다.
- **보안**: `TELEGRAM_BOT_TOKEN`, `ANTHROPIC_API_KEY`는 `.env`로만 로드하며 로그에 원문을 남기지
  않는다. `TELEGRAM_CHAT_ID`는 개인 채팅 ID로 민감정보는 아니나 마찬가지로 코드에 하드코딩하지
  않는다.
- **로깅/모니터링**: 표준 `logging` 모듈로 실행 시작/각 단계 결과/종료 코드를 기록해 Hermes 또는
  스케줄러가 실행 로그로 성공/실패를 판단할 수 있게 한다. `print`는 사용하지 않는다 (CLAUDE.md 3.4).

## 5. 입출력 명세
### 5.1 입력
| 항목 | 타입 | 필수 여부 | 유효성 규칙 | 설명 |
|---|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | 환경변수 | 필수 | 비어있지 않은 문자열 | 텔레그램 발송용 봇 토큰 |
| `TELEGRAM_CHAT_ID` | 환경변수 | 필수 | 비어있지 않은 문자열 | 결과를 받을 개인 채팅 ID |
| `ANTHROPIC_API_KEY` | 환경변수 | 필수 | 비어있지 않은 문자열 | 중국 남경 대회 검색용 Claude API 키 |
| DB 파일 경로 | 코드 상수 | 선택 | 존재하지 않으면 최초 실행 시 스키마 생성 | 기본값 `data/marathon.db` |
| 실행 인자 | 없음 | - | - | 커맨드라인 인자를 받지 않으며 실행 시점 날짜 기준으로 동작 |

### 5.2 출력
| 항목 | 타입 | 설명 |
|---|---|---|
| DB 반영 | SQLite upsert | `race` 테이블(PRD 4절 스키마)에 신규 삽입 또는 기존 레코드 갱신 |
| 텔레그램 메시지 | 텍스트 메시지 1건 | 접수중 + `notify_telegram=TRUE` 대회 목록 요약, 0건이면 안내 메시지 |
| 카카오톡 메시지(보조 채널) | 텍스트 메시지 1건 | 텔레그램과 동일한 내용을 "러닝97" 방에 전송(FR-11, best-effort) |
| 실행 로그 | 로그 파일/표준출력 | 수집 건수, 신규/갱신 건수, 소스별 성공/실패, 텔레그램/카카오톡 발송 결과 |
| 종료 코드 | 정수 | 완전 실패 시 0이 아닌 값, 그 외에는 0(카카오톡 발송 실패는 반영하지 않음) |

## 6. 상태/흐름
```
[시작]
  └ .env 로드 → 값 누락 시 완전 실패로 종료 (FR-1)
[수집]
  ├ 한국: marathonmate.store 크롤링 → 성공/실패
  └ 중국: Claude web_search 호출 → 성공/실패
      └ 둘 다 실패 → 완전 실패로 종료 (로그 남기고 0이 아닌 종료 코드)
      └ 한쪽만 실패 → 로그 남기고 성공한 쪽 결과로 계속 진행
[정규화] 공통 스키마로 변환 (FR-4)
[DB 반영]
  ├ 기존 레코드 있음 (country+race_name+race_date 일치) → updated_at만 갱신, notify_telegram 유지
  └ 기존 레코드 없음 → 신규 삽입, notify_telegram=TRUE, first_found_at=now
[조회] notify_telegram=TRUE AND 현재 접수중 레코드 조회
[발송(텔레그램)]
  ├ 0건 → 안내 메시지 발송
  └ 1건 이상 → 목록 요약 메시지 발송
      └ 발송 실패 → 완전 실패로 종료 (카카오톡 발송은 시도하지 않음)
[발송(카카오톡, 보조 채널, FR-11)]
  └ 텔레그램과 동일한 메시지를 "러닝97" 방에 전송 시도
      └ 실패해도 로그만 남기고 계속 진행(완전 실패로 치지 않음)
[종료] 로그 기록 후 종료 코드 반환
```
- 이미 DB에 있던 대회가 이번 실행에서 "접수 마감"으로 바뀐 경우: 레코드는 삭제하지 않고
  `updated_at`만 갱신한다. 조회 단계의 "현재 접수중" 조건에서 자연히 제외되므로 텔레그램에는
  더 이상 나타나지 않는다.
- 이번 실행에서 중국/한국 소스에 더 이상 나타나지 않는(사이트에서 사라진) 기존 레코드는 이번
  버전에서는 별도로 삭제하거나 상태를 변경하지 않는다 (PRD/이 SRS의 비범위).

## 7. 예외 처리
| 상황 | 처리 방식 |
|---|---|
| `.env` 필수 값 누락 | 실행 시작 전 에러 로그 남기고 0이 아닌 종료 코드로 즉시 종료 |
| `marathonmate.store` 목록 페이지 요청 실패/타임아웃(연결 오류, 타임아웃, 5xx) | 1초·2초 간격으로 최대 2회 재시도(총 3회 시도), 재시도 시마다 경고 로그. 3회 모두 실패하면 한국 소스 실패로 로그 남기고, 중국 결과만으로 계속 진행 (FR-10) |
| `marathonmate.store` 목록 페이지 4xx 응답(잘못된 요청 등) | 재시도해도 결과가 같으므로 즉시 한국 소스 실패로 로그 남기고, 중국 결과만으로 계속 진행 |
| `marathonmate.store` HTML 구조 변경으로 파싱 결과 0건 | 한국 소스 실패로 간주하고 원본 HTML 일부를 로그에 남겨 추후 파싱 로직 보완 근거로 사용 |
| Claude API 호출 실패/타임아웃 | 중국 소스 실패로 로그 남기고, 한국 결과만으로 계속 진행 |
| Claude 응답이 JSON 형식이 아니거나 파싱 실패 | 이번 실행의 중국 결과를 0건으로 처리하고, 원본 응답 텍스트를 로그에 남겨 프롬프트 보완 근거로 사용 (PRD 6절) |
| 한국·중국 소스 모두 실패 | 완전 실패로 처리, 에러 로그 남기고 0이 아닌 종료 코드로 종료 (텔레그램 발송 시도하지 않음) |
| DB 파일 쓰기 실패(잠금 등) | 에러 로그 남기고 0이 아닌 종료 코드로 종료 |
| 텔레그램 전송 실패 (네트워크/토큰 오류 등) | DB 반영은 이미 완료된 상태로 유지하고, 에러 로그 남긴 뒤 0이 아닌 종료 코드로 종료(카카오톡 발송은 시도하지 않음) |
| 카카오톡 전송 실패(`kakaotalk_sender` 비정상 종료/예외) | 에러 로그만 남기고 계속 진행. 텔레그램 발송·DB 반영 결과나 종료 코드에는 영향 없음(FR-11) |

## 8. 외부 의존성
- **외부 API/서비스**: `marathonmate.store` (크롤링 대상, 인증 불필요), Anthropic Messages API
  (`web_search` 도구), Telegram Bot API
- **보조 채널**: `kakaotalk_sender` 스킬(2026-08-20 추가). 별도 외부 API가 아니라 저장소 내
  다른 스킬을 서브프로세스로 호출하는 것이며, `CLAUDE.md` 3.3(스킬 격리)에 따라 코드는
  import하지 않는다. 인증/자격증명 불필요 — 이미 로그인된 카카오톡 데스크톱 앱의 세션을
  그대로 사용한다(자세한 내용은 `kakaotalk_sender`의 `docs/SRS.md` 참고).
- **인증 방식 및 필요한 자격 증명**: `ANTHROPIC_API_KEY`(Claude API), `TELEGRAM_BOT_TOKEN` +
  `TELEGRAM_CHAT_ID`(텔레그램). `marathonmate.store`는 인증 불필요, `robots.txt` 크롤링 허용 확인됨
  (PRD 8.1절)
- **Python 패키지(초안)**: `requests`, `beautifulsoup4`, `anthropic`, `python-dotenv`,
  `sqlite3`(표준 라이브러리, DB), `subprocess`/`tempfile`(표준 라이브러리, 카카오톡 발송).
  정확한 버전은 골격 작성 단계에서 확정 (PRD 8.2절)
- **재시도/타임아웃 (운영 중 `ai_news_telegram`의 HN API 타임아웃 장애 대응 후 이 스킬에도
  동일 적용, FR-10)**: `marathonmate.store` 목록 페이지 요청만 타임아웃을 30초→45초로 늘리고,
  연결 오류/타임아웃/5xx에 한해 최대 3회 시도(1초·2초 백오프)로 재시도한다. 4xx는 재시도
  대상에서 제외한다. 대회 상세 페이지 요청과 Claude 호출, 텔레그램 발송은 대상이 아니다.
  카카오톡 발송도 재시도하지 않는다(`kakaotalk_sender`의 최대 실행 시간을 180초로 제한).

## 9. 테스트 시나리오
| 시나리오 | 입력 | 기대 결과 |
|---|---|---|
| 정상 케이스 (양쪽 성공, 신규 있음) | 한국/중국 모두 응답 성공, 신규 대회 포함 | DB에 신규 삽입, 텔레그램에 목록 발송, 종료 코드 0 |
| 신규 없음 | 양쪽 성공했으나 모두 기존 레코드와 동일 | DB는 `updated_at`만 갱신, `notify_telegram=TRUE`인 접수중 대회 있으면 그대로 발송(신규 여부와 무관하게 목록 발송) |
| 접수중인 대상 0건 | DB에 `notify_telegram=TRUE`이며 접수중인 레코드가 없음 | "접수중인 신규 대회가 없습니다" 안내 메시지 발송, 종료 코드 0 |
| 한국 목록 페이지 일시적 실패 후 회복 | 1~2번째 시도는 타임아웃, 3번째 시도에서 성공 | 재시도 경고 로그 남기고 정상 진행, 종료 코드 0 |
| 한국만 실패(재시도 소진) | `marathonmate.store` 목록 페이지 3회 모두 타임아웃, 중국 성공 | 한국 실패 로그 남기고 중국 결과로 DB 반영·발송 진행, 종료 코드 0 |
| 한국 목록 페이지 4xx 응답 | `marathonmate.store`가 404/400 반환, 중국 성공 | 재시도 없이 즉시 한국 실패 처리, 중국 결과로 계속 진행, 종료 코드 0 |
| 중국만 실패 | Claude API 에러, 한국 성공 | 중국 실패 로그 남기고 한국 결과로 DB 반영·발송 진행, 종료 코드 0 |
| 양쪽 모두 실패 | 두 소스 모두 에러 | DB 미반영, 텔레그램 미발송, 에러 로그, 종료 코드 0이 아님 |
| Claude 응답 파싱 실패 | Claude가 JSON이 아닌 텍스트 응답 | 중국 결과 0건으로 처리하고 원본 응답 로그, 한국 결과로 계속 진행 |
| 텔레그램 발송 실패 | 유효하지 않은 `TELEGRAM_BOT_TOKEN` | DB 반영은 유지, 발송 실패 로그, 종료 코드 0이 아님(카카오톡 발송은 시도 안 함) |
| 환경변수 누락 | `ANTHROPIC_API_KEY` 미설정 | 실행 시작 전 종료, 에러 로그, 종료 코드 0이 아님 |
| 카카오톡 발송 실패 | 텔레그램 발송 성공, `kakaotalk_sender`가 0이 아닌 종료 코드 반환 | 에러 로그만 남기고 종료 코드 0(텔레그램 성공 기준 그대로 유지, FR-11) |
| 카카오톡 발송 중 예외 | 텔레그램 발송 성공, `subprocess.run` 호출 자체가 예외 발생 | 예외를 밖으로 전파하지 않고 에러 로그만 남김, 종료 코드 0 |

## 10. 제약사항 / 비범위
- 정기 실행(주 1회 스케줄링) 로직은 포함하지 않는다 — Hermes 또는 OS 작업 스케줄러가 담당 (PRD 7절)
- 텔레그램 회신 제외 항목을 사용자가 체크/관리하는 기능은 이번 스킬의 범위가 아니다. `notify_telegram`
  컬럼은 조회 시 참조만 한다 (PRD 7절)
- 대회 신청(결제, 개인정보 입력 등) 자동화는 포함하지 않는다
- "남경 근방"은 남경시(江苏省 南京市) 행정구역 내 대회로 한정하며 상하이/쑤저우 등 인접 도시는
  포함하지 않는다
- 사이트/검색 결과에서 사라진 기존 DB 레코드를 자동으로 삭제하거나 "마감 확정" 상태로 표시하는
  기능은 이번 버전에 포함하지 않는다
- 재시도 정책은 `marathonmate.store` 목록 페이지 요청에만 적용한다(FR-10). 대회 상세 페이지
  요청, Claude API 호출, 텔레그램 발송은 이번 버전에서도 재시도하지 않는다(4절 참고)
