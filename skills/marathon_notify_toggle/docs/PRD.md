# PRD: marathon_notify_toggle

- 작성일: 2026-08-05
- 작성자: devjan
- 상태: 초안

## 1. 배경 및 목적
[marathon_finder](../../marathon_finder/) 스킬은 한국/중국 남경의 접수중인 대회를 찾아
`data/marathon.db`의 `race` 테이블에 저장하고, `notify_telegram=TRUE`인 대회만 텔레그램으로
요약 발송한다. `race` 테이블에는 이미 `notify_telegram` 컬럼이 있지만, marathon_finder는 신규
삽입 시 이 값을 `TRUE`로 설정하고 조회 시 참조만 할 뿐, 값을 바꾸는 기능은 없다
(marathon_finder PRD 7절에 "제외 기능 자체는 이후 별도 PRD로 다룬다"로 명시됨).

실제로 신청을 완료했거나 더 이상 관심이 없는 대회도 매주 반복해서 텔레그램 알림에 나타나
목록이 불필요하게 길어지는 문제가 있다. 반대로, 한 번 제외했던 대회를 다시 챙겨보고 싶어지는
경우(예: 신청을 취소했거나 마음이 바뀐 경우)도 있다. 이 스킬은 사용자가 Hermes에게 "OO마라톤
알림 그만 보내줘" 또는 "OO마라톤 알림 다시 켜줘" 같은 자연어로 요청하면, DB에서 해당 대회를
찾아 `notify_telegram` 값을 `FALSE`(해제) 또는 `TRUE`(재활성화)로 바꿔준다.

## 2. 트리거 조건
- 이 스킬 자체는 정기 실행이나 자동 트리거를 갖지 않는다. Hermes가 사용자의 자연어 요청을
  해석해 커맨드라인 인자로 변환한 뒤 `python src/main.py`를 호출하는 방식으로만 실행된다.
- Hermes가 이 스킬을 "해제" 동작으로 선택해야 하는 사용자 발화 예시:
  - "춘천마라톤 알림 그만 보내줘"
  - "그 대회 이제 알림에서 빼줘 / 제외해줘"
  - "OO 대회 신청했으니까 더 이상 안 알려줘도 돼"
- Hermes가 이 스킬을 "재활성화" 동작으로 선택해야 하는 사용자 발화 예시:
  - "OO마라톤 알림 다시 켜줘"
  - "그 대회 다시 알려줘 / 다시 받아볼래"
  - "신청 취소했으니까 다시 알림 목록에 넣어줘"
- `trigger_keywords`(6절 skill.yaml 참고)에는 "알림 해제", "알림 끄기", "알림 켜기", "알림 다시
  받기", "대회 제외", "대회 다시 포함" 등을 등록한다.
- Hermes는 사용자 발화에서 대회를 식별할 단서(대회명 전체 또는 일부, 가능하면 국가/날짜)와
  원하는 동작(해제/재활성화)을 추출해 커맨드라인 인자로 전달한다. 정확한 레코드를 특정할 수
  없는 단서만 있다면, 이 스킬은 후보 목록을 반환하므로 Hermes가 그 목록을 사용자에게 보여주고
  재질의한 뒤 다시 호출한다.

## 3. 입력
| 항목 | 타입 | 필수 여부 | 설명 |
|---|---|---|---|
| `--disable` | 커맨드라인 플래그 | 필수(택 1) | 매칭된 대회의 `notify_telegram`을 `FALSE`로 설정(알림 해제) |
| `--enable` | 커맨드라인 플래그 | 필수(택 1) | 매칭된 대회의 `notify_telegram`을 `TRUE`로 설정(알림 재활성화) |
| `--name` | 커맨드라인 인자(문자열) | `--id` 미사용 시 필수 | 대회명 부분 일치 검색어(`LIKE '%값%'`, 대소문자 무관). 예: `"춘천"` |
| `--country` | 커맨드라인 인자(`KR`/`CN`) | 선택 | 국가로 후보를 좁힐 때 사용 |
| `--race-date` | 커맨드라인 인자(`YYYY-MM-DD`) | 선택 | 대회 개최일로 후보를 좁힐 때 사용 (동명 대회가 매년 반복되는 경우 구분용) |
| `--id` | 커맨드라인 인자(정수) | `--name` 미사용 시 필수 | `race.id`를 이미 알고 있을 때(예: 직전 실행에서 후보 목록으로 확인한 경우) 단일 레코드를 바로 지정 |
| `--list` | 커맨드라인 플래그 | 선택 | 매칭 없이 전체 대회 목록과 각 대회의 현재 `notify_telegram` 값을 조회해서 출력 (Hermes가 사용자에게 후보를 먼저 보여주거나 현재 상태를 확인할 때 사용). `--disable`/`--enable`/`--name`/`--id`보다 우선 적용 |
| DB 파일 경로 | 코드 상수 | 선택 | 기본값 `data/marathon.db` (marathon_finder와 동일 파일, 저장소 최상위 `data/` 공용 — `CLAUDE.md` 2절) |

- `--disable`과 `--enable`은 상호 배타적이며, `--list`를 쓰지 않는 한 반드시 하나를 지정해야
  한다. 둘 다 지정되면 인자 오류로 처리하고 실행 전 종료한다.
- `--name`과 `--id`는 최소 하나가 필요하며(`--list` 사용 시 예외), 실행 시 상호 배타적이다.
  둘 다 주어지면 `--id`를 우선한다.
- `--name`은 부분 일치이므로 여러 레코드가 매칭될 수 있다(5절 처리 흐름 참고).

## 4. 출력
- **DB 반영**: 매칭이 정확히 1건으로 좁혀진 경우, 해당 레코드의 `notify_telegram`을 지정한
  동작(`--disable`→`FALSE`, `--enable`→`TRUE`)에 맞게 갱신하고 `updated_at`을 현재 시각으로
  갱신한다. 그 외 컬럼(대회명/날짜/장소 등)은 건드리지 않는다.
- **표준출력/로그**: 아래 중 하나를 사람이 읽을 수 있는 형식과 함께 반환한다 (Hermes가 그대로
  사용자에게 보여줄 수 있도록).
  - 성공: 어떤 대회(국가/대회명/날짜)의 알림이 해제/재활성화됐는지 1건 요약
  - 매칭 0건: "조건에 맞는 대회를 찾지 못했습니다" + 검색에 사용한 조건
  - 매칭 2건 이상: 후보 목록(`id`, `country`, `race_name`, `race_date`, 현재 `notify_telegram`
    값)을 표 형태로 출력하고, `--id` 또는 `--race-date`를 추가해 다시 실행하라는 안내
  - `--list` 사용 시: 전체 대회 목록과 각 대회의 현재 `notify_telegram` 값
- **종료 코드**: 성공(정확히 1건 갱신, 또는 이미 원하는 상태였던 경우) 시 `0`, 그 외(0건/다건
  매칭, DB 오류, 인자 오류 등)는 0이 아닌 값. Hermes는 종료 코드로 사용자에게 추가 확인이
  필요한지 판단한다.

## 5. 처리 흐름 (개요)
1. 커맨드라인 인자를 파싱한다. `--disable`/`--enable` 동시 지정 등 잘못된 조합이면 인자 오류로
   즉시 종료한다. `--list`가 있으면 4절의 목록 출력만 하고 종료한다.
2. `--id`가 있으면 해당 `id`로 단건 조회한다. 없으면 `--name`(부분 일치) + 선택적
   `--country`/`--race-date` 조건으로 `race` 테이블을 조회한다.
3. 조회 결과가 0건이면 실패로 처리하고 안내 메시지를 출력한다.
4. 조회 결과가 2건 이상이면 갱신하지 않고 후보 목록을 출력한다(모호한 상태로 임의 추측하지
   않는다).
5. 조회 결과가 정확히 1건이면, 지정된 동작에 따라 처리한다:
   - `--disable`이고 이미 `notify_telegram=FALSE`인 경우: DB는 그대로 두고 "이미 알림이 해제된
     대회입니다" 안내와 함께 성공으로 종료한다(멱등성 보장).
   - `--disable`이고 `notify_telegram=TRUE`인 경우: `FALSE`로 갱신하고 `updated_at`을 현재
     시각으로 갱신한다.
   - `--enable`이고 이미 `notify_telegram=TRUE`인 경우: DB는 그대로 두고 "이미 알림을 받고 있는
     대회입니다" 안내와 함께 성공으로 종료한다(멱등성 보장).
   - `--enable`이고 `notify_telegram=FALSE`인 경우: `TRUE`로 갱신하고 `updated_at`을 현재
     시각으로 갱신한다.
6. 처리 결과(검색 조건, 요청 동작, 매칭 건수, 갱신 여부)를 `logging` 모듈로 기록한다.

## 6. 성공/실패 기준
- **성공**: 정확히 1건이 특정되어 요청한 동작대로 `notify_telegram`이 갱신되거나(또는 이미 그
  상태였거나), `--list` 조회가 정상적으로 출력됐을 때. 종료 코드 `0`.
- **실패(사용자 재입력 필요)**: 매칭 0건 또는 2건 이상. 이 경우 DB는 변경하지 않고, 사용자가
  조건을 좁혀 다시 요청할 수 있도록 원인과 후보를 명확히 알려준다. 종료 코드는 0이 아니지만
  프로그램 오류가 아니라 "추가 정보 필요" 상태임을 메시지로 구분한다.
- **실패(시스템 오류)**: DB 파일이 없거나 쓰기 실패(잠금 등), 인자 파싱 실패(`--disable`/
  `--enable` 둘 다 없거나 둘 다 있음, `--name`/`--id` 모두 없이 `--list`도 없이 실행 등). 에러
  로그를 남기고 0이 아닌 종료 코드로 종료한다.

## 7. 제약사항 / 비범위
- 대회 레코드 자체의 삭제, 신규 추가, 날짜/장소 등 다른 컬럼 수정은 다루지 않는다. 오직
  `notify_telegram` 컬럼을 `TRUE`/`FALSE`로 바꾸는 것만이 이 스킬의 책임이다.
- 텔레그램으로 처리 결과를 별도 발송하는 기능은 포함하지 않는다. 실행 결과는 표준출력/로그로만
  제공하며, Hermes가 이를 받아 대화창에서 사용자에게 전달하는 것을 전제로 한다.
- 여러 건을 한 번에 일괄 해제/재활성화하는 기능(`--all` 등)은 이번 버전에 포함하지 않는다.
  모호한 매칭은 항상 사람이 개입해 후보 중 하나를 특정하도록 한다(오작동으로 여러 대회의 알림이
  한꺼번에 바뀌는 것을 방지).
- `race` 테이블 스키마는 marathon_finder PRD 4절의 기존 스키마를 그대로 사용하며, 이 스킬은
  새 컬럼이나 새 테이블을 추가하지 않는다.

## 8. 의존성
- **외부 서비스/API**: 없음 (로컬 SQLite 파일만 다룸)
- **공유 데이터**: `data/marathon.db`의 `race` 테이블 (marathon_finder가 채워 넣은 동일 DB를
  공유, `CLAUDE.md` 2절 원칙에 따라 스킬 폴더 밖 공용 `data/`에 위치)
- **Python 패키지(초안)**: `sqlite3`(표준 라이브러리), `argparse`(표준 라이브러리, 커맨드라인
  인자 파싱). 외부 API를 호출하지 않으므로 `python-dotenv` 등 `.env` 의존성은 없다.
