# PRD: marathon_search

- 작성일: 2026-08-05
- 작성자: devjan
- 상태: 초안

## 1. 배경 및 목적
[marathon_finder](../../marathon_finder/)는 매 실행마다 `notify_telegram=TRUE`이고 이번 실행에서
수집된 대회만 텔레그램으로 요약 발송하며, [marathon_notify_toggle](../../marathon_notify_toggle/)은
특정 대회의 알림 여부만 켜고 끈다. 두 스킬 모두 `data/marathon.db`의 `race` 테이블 전체를 사용자가
원하는 조건으로 자유롭게 들여다볼 수는 없다.

사용자는 정기 발송을 기다리지 않고 "서울에서 열리는 대회 알려줘", "9월에 있는 대회 뭐 있어",
"춘천 아니면 서울에서 하는 대회 찾아줘", "알림 꺼둔 대회 뭐가 있었지" 같은 질문을 Hermes에게
바로 던지고 답을 받고 싶어한다. 이 스킬은 `race` 테이블을 읽기 전용으로 검색해, 알림 여부/기간/
장소/대회명 조건을 하나 이상 조합(AND 또는 OR)해 필터링한 결과를 돌려준다.

## 2. 트리거 조건
- 이 스킬 자체는 정기 실행이나 자동 트리거를 갖지 않는다. Hermes가 사용자의 자연어 요청을
  해석해 커맨드라인 인자로 변환한 뒤 `python src/main.py`를 호출하고, 표준출력 결과를 그대로
  받아 사용자에게 회신하는 방식으로만 실행된다.
- Hermes가 이 스킬을 선택해야 하는 사용자 발화 예시:
  - "서울에서 열리는 마라톤 알려줘" (장소 단일 조건)
  - "9월에 있는 대회 찾아줘" / "이번 주말 대회 뭐 있어" (기간 단일 조건)
  - "춘천마라톤 접수 정보 알려줘" (이름 단일 조건)
  - "지금 알림 꺼둔 대회 목록 보여줘" (알림 상태 단일 조건)
  - "9월에 서울에서 하는 대회 찾아줘" (기간 AND 장소)
  - "춘천 아니면 서울에서 하는 대회 알려줘" (장소 OR, 다만 이번 버전은 카테고리 간 결합만
    지원하므로 이 예시는 `--location` 값 매칭 범위 안에서 처리되거나 Hermes가 2회 호출 후
    합쳐서 답해야 한다 — 7절 비범위 참고)
- `trigger_keywords`(6절 skill.yaml 참고)에는 "마라톤 검색", "대회 검색", "마라톤 조회", "대회
  찾기", "마라톤 필터" 등을 등록한다.
- Hermes는 사용자 발화에서 필터 조건(알림 여부/기간/장소/대회명 중 1개 이상)과, 조건이 2개
  이상이면 결합 방식(AND/OR)을 추출해 커맨드라인 인자로 전달한다.

## 3. 입력
| 항목 | 타입 | 필수 여부 | 설명 |
|---|---|---|---|
| `--notify` | 커맨드라인 인자(`on`/`off`) | 선택 | `notify_telegram` 필터. `on`=`TRUE`, `off`=`FALSE` |
| `--date-from` | 커맨드라인 인자(`YYYY-MM-DD`) | 선택 | 대회 개최일(`race_date`) 하한. "기간" 필터의 일부 |
| `--date-to` | 커맨드라인 인자(`YYYY-MM-DD`) | 선택 | 대회 개최일(`race_date`) 상한. "기간" 필터의 일부 |
| `--location` | 커맨드라인 인자(문자열) | 선택 | `location` 부분 일치 검색어(대소문자 무관) |
| `--name` | 커맨드라인 인자(문자열) | 선택 | `race_name` 부분 일치 검색어(대소문자 무관) |
| `--match` | 커맨드라인 인자(`and`/`or`, 기본값 `and`) | 선택 | 지정된 필터 카테고리(4절 참고)가 2개 이상일 때 이들을 AND/OR 중 무엇으로 결합할지 결정. 카테고리가 1개 이하면 값과 무관하게 동작에 영향 없음 |
| DB 파일 경로 | 코드 상수 | 선택 | 기본값 `data/marathon.db` (marathon_finder/marathon_notify_toggle과 동일 파일, 저장소 최상위 `data/` 공용 — `CLAUDE.md` 2절) |

- 필터 카테고리는 4개다: **알림**(`--notify`), **기간**(`--date-from`/`--date-to`), **장소**
  (`--location`), **대회명**(`--name`). 이 중 최소 1개 카테고리는 반드시 지정해야 한다(전체
  조회는 이 스킬의 목적이 아니다).
- "기간" 카테고리는 `--date-from`과 `--date-to` 중 하나만 줘도 된다(각각 하한만/상한만 있는
  열린 범위). 둘 다 주면 카테고리 내부에서는 항상 AND(`race_date >= 하한 AND race_date <= 상한`)로
  결합되며, `--match`의 영향을 받지 않는다.
- `--match`는 카테고리와 카테고리 "사이"에만 적용된다. 예: `--notify on --location 서울 --match or`
  → `notify_telegram=TRUE OR location LIKE '%서울%'`.

## 4. 출력
- **DB 조회만 수행**(읽기 전용). 어떤 컬럼도 갱신하지 않는다.
- **표준출력**: 조건에 맞는 대회 목록을 사람이 읽을 수 있는 형식으로 반환한다 (Hermes가 그대로
  사용자에게 전달할 수 있도록).
  - 매칭 1건 이상: 총 건수 헤더 + 대회별 국가/대회명/개최일/장소/거리/접수마감일/신청링크/현재
    알림 상태(`ON`/`OFF`)를 `race_date` 오름차순으로 나열
  - 매칭 0건: "조건에 맞는 대회를 찾지 못했습니다" + 사용된 검색 조건 요약 (오류가 아니라
    정상적인 검색 결과임을 명확히 함)
- **로그**: 사용된 필터 조건, 결합 방식(`--match`), 매칭 건수를 `logging` 모듈로 기록한다.
- **종료 코드**: 인자 검증과 DB 조회가 정상적으로 끝나면 매칭 건수와 무관하게 `0`. 인자 오류나
  DB 오류일 때만 0이 아닌 값을 반환한다 (6절 참고).

## 5. 처리 흐름 (개요)
1. 커맨드라인 인자를 파싱한다.
2. 인자를 검증한다: 4개 카테고리(알림/기간/장소/대회명) 중 하나도 지정되지 않았으면 인자
   오류로 종료한다. `--date-from`/`--date-to`가 `YYYY-MM-DD` 형식이 아니거나, 둘 다 있는데
   `--date-from`이 `--date-to`보다 미래이면 인자 오류로 종료한다.
3. 지정된 카테고리마다 SQL 조건을 만든다(3절 참고).
4. `--match`(기본 `and`)로 카테고리 조건들을 결합해 최종 `WHERE` 절을 구성한다.
5. `race` 테이블을 조회하고 `race_date` 오름차순으로 정렬한다.
6. 결과를 4절 형식으로 출력한다(0건이어도 정상 종료).
7. 검색 조건/결합 방식/매칭 건수를 로그로 남긴다.

## 6. 성공/실패 기준
- **성공**: 인자 검증을 통과하고 DB 조회가 정상적으로 끝났을 때. 매칭 건수가 0이어도 성공이다
  (검색 결과가 없다는 것도 유효한 답이다). 종료 코드 `0`.
- **실패(인자 오류)**: 필터 카테고리를 하나도 지정하지 않음, 날짜 형식이 `YYYY-MM-DD`가 아님,
  `--date-from`이 `--date-to`보다 미래인 범위. 에러 메시지를 출력하고 0이 아닌 종료 코드로
  종료한다(DB에 접근하지 않음).
- **실패(시스템 오류)**: DB 파일이 없거나 조회 중 오류(잠금 등)가 발생한 경우. 에러 로그를
  남기고 0이 아닌 종료 코드로 종료한다.

## 7. 제약사항 / 비범위
- 읽기 전용이다. `notify_telegram` 값을 바꾸는 것은 [marathon_notify_toggle](../../marathon_notify_toggle/)의
  책임이며, 이 스킬은 어떤 컬럼도 갱신하지 않는다.
- 카테고리 "사이"의 결합 방식(`--match`)만 AND/OR을 지원한다. 같은 카테고리 안에서 "이 이름 또는
  저 이름"처럼 값 단위 OR 검색(예: 장소가 "춘천" 또는 "서울")은 이번 버전에 포함하지 않는다.
  이런 요청은 Hermes가 이 스킬을 조건별로 여러 번 호출해 결과를 합쳐 사용자에게 답하거나,
  이후 버전에서 `--location`/`--name`에 다중 값을 허용하는 방식으로 확장한다.
- `--country`(국가) 단독 필터는 제공하지 않는다. 국가로 좁히고 싶으면 `--location`에 지역명을
  포함해 검색하거나, 이후 버전에서 국가 필터를 추가한다.
- "기간" 필터는 `race_date`(대회 개최일) 기준이다. `registration_start`/`registration_end`
  (접수 기간) 기준 검색은 이번 버전에 포함하지 않는다. 접수 마감이 임박한 대회를 찾는 기능이
  필요해지면 별도 옵션으로 확장한다.
- 결과 개수 제한(페이지네이션, `--limit` 등)은 이번 버전에 포함하지 않는다. `race` 테이블
  규모가 작아(수십 건) 전체 반환에 문제가 없다고 판단했다. 데이터가 크게 늘어나면 이후
  버전에서 추가한다.
- 텔레그램 등 외부 채널로 결과를 별도 발송하는 기능은 포함하지 않는다. 표준출력만 제공하며,
  Hermes가 이를 받아 대화창에서 사용자에게 전달하는 것을 전제로 한다.
- `race` 테이블 스키마는 marathon_finder PRD 4절의 기존 스키마를 그대로 사용하며, 이 스킬은
  새 컬럼이나 새 테이블을 추가하지 않는다.

## 8. 의존성
- **외부 서비스/API**: 없음 (로컬 SQLite 파일만 읽음)
- **공유 데이터**: `data/marathon.db`의 `race` 테이블 (marathon_finder가 채워 넣고
  marathon_notify_toggle이 일부 갱신하는 동일 DB를 공유, `CLAUDE.md` 2절 원칙에 따라 스킬
  폴더 밖 공용 `data/`에 위치)
- **Python 패키지(초안)**: `sqlite3`(표준 라이브러리), `argparse`(표준 라이브러리, 커맨드라인
  인자 파싱). 외부 API를 호출하지 않으므로 `python-dotenv` 등 `.env` 의존성은 없다.
